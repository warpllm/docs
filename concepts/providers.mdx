warpllm routes requests to four providers: OpenAI, DeepSeek, Kimi, and OpenRouter. Every routable model is listed here with its context window, output token limit, and the environment variable you need to set. Pass the exact model string shown in the tables as your `model` field — the registry is strict and only the listed names are routable.

<Note>
Only the model strings listed on this page are routable. Passing an unlisted name — including a model that exists at the provider but is not in the warpllm registry — produces an `InvalidModel` error before any network request is made.
</Note>

All models listed here support both standard (non-streaming) and streaming chat completions. See [Streaming](/concepts/streaming) for how to use the streaming interface.

The Kimi platform is branded Kimi while the API host retains the Moonshot name, which is why the environment variable is `MOONSHOT_API_KEY`. Kimi does not publish a per-model output token ceiling, so the table shows only input (context window) sizes.

| Model string | Max input tokens |

<Info>
`kimi-k2.7-code` and `kimi-k2.7-code-highspeed` share the same context window and are optimized for code generation tasks. The `highspeed` variant prioritizes throughput.

## OpenRouter

<CardGroup cols={3}>
  <Card title="Base URL" icon="globe">
    `https://openrouter.ai/api/v1`
  </Card>
  <Card title="Environment variable" icon="key">
    `OPENROUTER_API_KEY`
  </Card>
  <Card title="Models" icon="list">
    9 models
  </Card>
</CardGroup>

OpenRouter is an aggregator — each model string routes to OpenRouter, which then fans out across multiple backend providers. The context window and output limits shown here are the **narrowest** any endpoint serving that model offers, because an unpinned request may land on any backend. Treat these figures as guaranteed minimums.

| Model string | Max input tokens | Max output tokens |
|---|---|---|
| `openrouter/anthropic/claude-opus-4` | 200,000 | 32,000 |
| `openrouter/anthropic/claude-sonnet-4` | 200,000 | 64,000 |
| `openrouter/auto` | — | — |
| `openrouter/google/gemini-2.5-pro` | 1,048,576 | 65,536 |
| `openrouter/moonshotai/kimi-k2.6` | 256,000 | — |
| `openrouter/moonshotai/kimi-k2.7-code` | 256,000 | — |
| `openrouter/moonshotai/kimi-k3` | 974,842 | — |
| `openrouter/openai/gpt-5.6` | 1,050,000 | 128,000 |
| `openrouter/~deepseek/deepseek-v4-flash-latest` | 1,048,576 | — |

<Accordion title="Why some OpenRouter models have no output limit listed">
OpenRouter routes a single model slug across many backend providers that can disagree on output token limits by a wide margin — for example, different backends serving `kimi-k2.6` cap output anywhere from 16,384 to 262,144 tokens. Quoting any single figure as the limit would be misleading, so warpllm omits it rather than promise a ceiling a routed request may not get.
</Accordion>

<Accordion title="What does openrouter/auto do?">
`openrouter/auto` is OpenRouter's own model-selection alias. When you use it, OpenRouter picks a backend model for each request based on its own routing logic. Because the model that actually handles the request varies, warpllm cannot record fixed context or output limits for it.
</Accordion>
